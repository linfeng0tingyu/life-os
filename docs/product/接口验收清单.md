# Life OS v0.1 接口验收清单

## 验收口径

本清单是 v0.1 API 的可测试合同。勾选一项表示该行为已有自动化测试且测试通过，而不是仅凭手工调用观察成功。接口路径以 `/api` 为统一前缀；除明确说明外，请求和响应均使用 JSON。

界面主题切换不属于 API 能力，不新增 `/api/theme` 或设置写接口。主题脚本只读写 `life-os.theme` 界面偏好并设置 `data-theme`，不得导入 API Client、调用 `fetch` 或改变任何业务响应。因而 M3 的接口合同和验收项保持不变。

成功响应统一为：

```json
{
  "success": true,
  "data": {}
}
```

失败响应统一为：

```json
{
  "success": false,
  "error": {
    "code": "validation_error",
    "message": "可供用户理解的错误说明",
    "details": {}
  }
}
```

## 通用合同

- [x] 所有接口使用正确的 HTTP 方法和状态码；未知路径返回 404，不伪装成成功响应。
- [x] 成功与失败响应符合统一包装，`Content-Type` 为 `application/json`。
- [x] 非法 JSON 返回 400，错误字段或不支持的媒体类型返回 400/415，不触发数据库写入。
- [x] 日期严格接受真实存在的 `YYYY-MM-DD`；例如 `2026-02-30` 返回 400。
- [x] 未知请求字段按统一策略拒绝或忽略；v0.1 建议拒绝并在 `details` 中指出字段名。
- [x] 记录不存在返回 404；唯一性或状态冲突返回 409；内部异常返回 500。
- [x] 任何失败写请求完整回滚，不产生部分更新或重复记录。
- [x] 响应不包含 Python traceback、本机绝对路径、数据库连接信息、日记正文之外的额外敏感内容。
- [x] 日志包含请求关联信息和可诊断错误，但不记录日记正文、健康详情或完整请求体。
- [x] 重复提交幂等的 PUT 请求得到同等最终状态，不产生重复每日记录。
- [x] 默认服务只绑定 `127.0.0.1`；接口不依赖云服务、浏览器 LocalStorage 或第三方网络资源。

## 日期聚合

### `GET /api/day/{date}`

- [x] 合法日期返回 200，`data` 至少包含 `date`、`calendar_day`、`habits`、`tasks`、`health`、`journal` 和 `finance`。
- [x] 完全没有数据的日期仍返回 200 和稳定的空结构，而不是 404。
- [x] `habits` 包含当天可记录习惯及其日志状态；不存在日志时返回未完成的可预测表示。
- [x] `tasks` 至少区分当天计划、当天到期、计划至到期区间覆盖当天的进行中任务和此前未完成逾期任务，并默认排除已归档任务；区间首尾日期按当天计划或当天到期归类。
- [x] 默认聚合不返回未排期或与目标日期无关的任务；Today 渲染当天计划、当天到期、区间覆盖今天的进行中任务和未完成逾期任务，并隐藏已完成、已取消状态。
- [x] Calendar 仍能从默认聚合读取所选日期已经完成或取消的任务，用于历史回看；Today 的隐藏规则不改写任务数据。
- [x] `health` 和 `journal` 在无记录时返回 `null` 或约定空对象；一经确定不得在不同日期间改变形状。
- [x] 切换日期不会返回其他日期的健康、日记或习惯日志。
- [x] 非法日期返回 400，且错误信息指出日期格式或日历值问题。

## 日历日期分类与标记

### `GET /api/calendar/month/{year-month}`

- [x] 合法月份返回该月每一天，数量与实际日历一致，并按日期升序排列。
- [x] 用户显式记录优先于官方节假日预置；官方预置优先于星期推断。没有前两者时，周一至周五返回 `workday`，周六和周日返回 `rest_day`。
- [x] 已内置的 2025、2026 年官方放假日和调休工作日返回 `source=official`、`explicit=false` 及相应节日名称或“调休上班”标签。
- [x] 显式记录覆盖星期推断，并返回 `holiday_name`、`custom_label`、`note`、`source` 和 `explicit=true`。
- [x] 每个日期返回 `has_data`，可指示该日是否存在显式标记或核心领域记录。
- [x] 每个日期返回稳定的 `habit_summary.completed` 与 `habit_summary.total`，且只统计当前启用习惯的完成数。
- [x] `2026-13`、不完整年月等非法参数返回 400。

### `PUT /api/calendar/days/{date}`

- [x] 接受 `day_type=workday|rest_day`，并可选接受节假日名称、自定义标签和备注。
- [x] 普通工作日可以覆盖为休息日，周末可以覆盖为调休工作日。
- [x] 对同一日期重复 PUT 更新原记录，不产生第二条数据库记录。
- [x] 已归档日期再次 PUT 时恢复原记录并清空 `archived_at`。
- [x] 非法日期、日期类型、来源或超长文本返回 400，原记录保持不变。

### `DELETE /api/calendar/days/{date}`

- [x] 清除采用归档方式，不物理删除数据库行。
- [x] 清除后优先恢复官方节假日预置；不存在官方预置时恢复星期推断，月历和日期聚合不再返回用户显式标签。
- [x] 没有有效显式记录时返回 404；重复删除不会产生新记录。

## 任务、习惯与财务分类

### `GET /api/categories?scope={task|habit|finance}`

- [x] `scope` 为必填且只接受 `task`、`habit` 或 `finance`，缺失或非法值返回 400。
- [x] 任务、习惯与财务分类相互隔离，并按 `sort_order`、名称、`id` 稳定排序。
- [x] 没有分类时返回 200 和空数组。

### `POST /api/categories`

- [x] 接受 `scope`、`name` 和可选 `sort_order`，成功返回 201 与数据库生成的 `id`。
- [x] 名称去除首尾空白，同一作用域内不区分大小写唯一；重复名称返回 409。
- [x] 任务或习惯写入分类时必须引用对应作用域的已创建名称；未知或跨作用域分类返回 400 且不写入。财务页面使用 `finance` 单选项，接口保留旧自由文本流水的兼容读取。

### `PUT /api/categories/order`

- [x] 请求必须提供合法 `scope` 和该作用域全部、不重复的分类 ID；缺项、重复、跨作用域或未知 ID 返回 400，原顺序保持不变。
- [x] 排序在单一事务中归一为稳定间隔，成功响应和后续列表查询顺序一致，不产生半完成排序。

### `DELETE /api/categories/{id}`

- [x] 未被任何记录引用的分类可物理删除，返回被删除 ID；不存在的 ID 返回 404。
- [x] 当前或历史任务、习惯、财务流水仍引用分类时返回 409、引用数量、最多 20 条具体引用及是否截断；财务引用包含日期、金额、类型和归档状态，不清空、不改写业务记录。
- [x] 任务、习惯、日历未来规划和财务表单共享同一分类组件；选择与管理均可搜索，选择列表和管理列表超过固定高度后内部滚动。

## 习惯

### `GET /api/habits`

- [x] 默认只返回启用习惯，并按 `sort_order`、`id` 稳定排序。
- [x] `include_inactive=true` 时返回停用习惯；非法布尔参数返回 400。
- [x] 空列表返回 200 和 `[]`。

### `POST /api/habits`

- [x] 提供有效 `name` 可创建习惯，返回 201 和数据库生成的 `id`。
- [x] 名称会去除首尾空白；空名称返回 400。
- [x] 未提供可选字段时应用明确默认值：`active=true`、`sort_order=0`。
- [x] 客户端提交 `id`、`created_at` 等只读字段时按通用策略拒绝。
- [x] 分类只接受 `categories.scope=habit` 中已创建的单选值，也允许 `null` 表示未分类。

### `PUT /api/habits/{id}`

- [x] 可更新名称、说明、图标、分类、启用状态和排序。
- [x] 停用后默认列表不再返回该习惯，但既有 `habit_logs` 保持不变。
- [x] 重新启用使用原 `id` 和历史记录。
- [x] 不存在的 `id` 返回 404；非法字段不产生部分更新。

### `PUT /api/habits/{id}/log/{date}`

- [x] 首次写入创建当天日志并固定返回 200。
- [x] 对相同习惯和日期重复 PUT 执行更新，不产生第二条记录。
- [x] 支持 `status`，并可选支持 `value`、`value_unit` 和 `note`。
- [x] 不存在的习惯返回 404；停用习惯允许补录历史日期。
- [x] 非法日期、非法布尔值或非数值 `value` 返回 400。

### `GET /api/habits/statistics?period={week|month|year}&anchor={date}`

- [x] 周使用周一至周日，月使用自然月，年使用自然年；周/月返回逐日桶，年返回 12 个逐月桶。
- [x] 当前周期的未来日期返回 `null` 且不进入坚持率分母，过去空缺日期返回 0 次完成。
- [x] 汇总返回统计习惯数、完成次数和有完成的日期数；明细返回完成天数、有效天数、坚持率、当前连续与区间最长连续天数。
- [x] 停用习惯在区间内存在完成记录时仍可见，但 `completion_rate` 为 `null`，不推断不存在的历史停用时间。
- [x] 日志按区间批量读取，不按日期或习惯执行 N+1 查询；非法周期或日期返回 400。

## 任务

### `GET /api/tasks`

- [x] 无筛选时返回未归档任务，并采用稳定排序。
- [x] 支持 `date`、`status` 和 `include_archived` 筛选；组合筛选结果正确。
- [x] `date` 筛选同时覆盖计划于该日、到期于该日和此前逾期未完成任务，响应以 `date_match` 保持可区分。
- [x] 非法枚举或日期参数返回 400。

### `POST /api/tasks`

- [x] 仅提供有效 `title` 即可创建无日期任务，返回 201。
- [x] 可设置描述、状态、优先级、分类、计划日期、到期日期、排序和父任务。
- [x] 空标题、非法状态、非法优先级或非法日期返回 400。
- [x] 不存在的 `parent_id` 返回 404；自引用和父子循环被拒绝。
- [x] 初始状态为 `done` 时设置 `completed_at`，其他状态不设置。
- [x] 分类只接受 `categories.scope=task` 中已创建的单选值，也允许 `null` 表示未分类。

### `PUT /api/tasks/{id}`

- [x] 可更新所有允许编辑的业务字段，未提供字段保持原值。
- [x] 状态进入 `done` 时设置 `completed_at`；离开 `done` 时按模型规则清空。
- [x] 任务不能成为自身或其后代的子任务。
- [x] 不存在或已归档任务的更新行为明确；v0.1 默认已归档任务需显式恢复后才能编辑。
- [x] 校验失败时原记录所有字段保持不变。

### `DELETE /api/tasks/{id}`

- [x] 执行软删除/归档并返回 200 与归档结果，不物理删除数据库行。
- [x] 归档后默认任务查询和日期聚合不再返回该任务。
- [x] 使用 `include_archived=true` 仍可查询该记录。
- [x] 对已归档任务重复调用具有幂等结果；不存在的 `id` 返回 404。

### `POST /api/tasks/{id}/restore`

- [x] 已归档任务恢复后继续使用原 `id`，`archived_at` 被清空，并重新进入默认查询和对应日期聚合。
- [x] 对未归档任务重复调用具有幂等结果，不创建新任务或改变其他业务字段。
- [x] 不存在的 `id` 返回 404；空 JSON 对象和无请求体均可调用。

## 生活节律与健康状态

### `GET /api/health/{date}`

- [x] 存在记录时返回完整健康对象；无记录时返回 200 和 `data: null`。
- [x] 返回睡眠情况、运动分钟和已选运动种类；旧版精确睡眠字段仍可读取，以保护已有数据。
- [x] 非法日期返回 400。

### `PUT /api/health/{date}`

- [x] 首次 PUT 创建记录，后续 PUT 更新同一条记录，不产生重复日期。
- [x] 允许仅填写一个健康字段，未提供字段不会被意外清空。
- [x] `energy_level`、`mood_level` 仅接受 1–5 或 `null`。
- [x] 体重必须为正数，运动分钟不得为负，非法值返回 400。
- [x] `sleep_status` 仅接受五个约定区间或 `null`；当前 HTTP 接口拒绝旧精确睡眠写入字段。
- [x] `exercise_type_ids` 必须为不重复且全部存在的整数列表；空列表清空当天运动种类。
- [x] 旧 `sleep_start`、`sleep_end`、`sleep_duration_minutes`、`sleep_duration_manual` 与 `sleep_quality` 保持可读取和可导出，但不再属于健康接口的直接编辑字段。
- [x] 清空可选字段需使用约定的 `null`，并能与“未提供该字段”区分。

### `GET /api/health/statistics?period={week|month|year}&anchor={date}`

- [x] 周/月返回逐日序列，年返回 12 个逐月桶；当前周期的未来桶不伪造零值。
- [x] 睡眠情况返回各区间有效天数分布，不读取旧版精确睡眠时长；运动返回总分钟、平均分钟、活动日数和各运动种类频次，并在逐日序列返回运动种类名称。
- [x] 体重返回首值、末值、变化、最低和最高值；精力、情绪与身体状态按实际有效记录汇总。
- [x] 缺失值保持 `null`，不按零补齐、不插值；非法周期或日期返回 400。

### 运动种类管理

- [x] `GET /api/exercise-types` 按自定义顺序返回全部选项。
- [x] `POST /api/exercise-types` 创建大小写不敏感的唯一名称；重复名称返回 409。
- [x] `PUT /api/exercise-types/order` 必须提交完整且不重复的 ID 列表。
- [x] `DELETE /api/exercise-types/{id}` 只删除未被任何节律记录使用的选项；仍在使用时返回 409。
- [x] Today 与独立节律页使用同一组运动种类和 `/api/health/{date}` 数据；Today 只写设备当天的睡眠情况、运动种类、精力和情绪，不清空其他详细字段。
- [x] Today 与独立节律页的运动种类均使用有最大高度和内部滚动的摘要式多选下拉框；Today 的紧凑下拉层与所在字段同宽，选项完整可见，不撑大卡片或产生卡片横向滚动。Today 不显示新建或管理入口，新增、搜索、排序和删除集中在独立节律页。

## 日记

### `GET /api/journal/{date}`

- [x] 存在日记时返回 Markdown 原文和更新时间；无记录时返回 200 和 `data: null`。
- [x] 不对 Markdown 内容做有损转换；前端渲染时另行执行安全处理。
- [x] 非法日期返回 400。

### `PUT /api/journal/{date}`

- [x] 仅设备本地今天允许首次创建或更新，非今天返回 409；同日反复 PUT 始终只有一行。
- [x] 接受空字符串并按模型规则保存；缺少 `content` 字段返回 400。
- [x] 中文、换行、常见 Markdown 和 Unicode 字符往返后保持一致。
- [x] 快速连续保存时最终内容是最后一次已成功请求的内容，旧响应不会覆盖新状态。
- [x] 模拟数据库失败时返回错误，原内容保持不变。

### `GET /api/journal/month/{year-month}`

- [x] 合法年月返回该月已有日记的日期和更新时间，按日期升序排列，不批量暴露正文。
- [x] 空月份返回 200 和空数组，非法年月或不存在的月份返回 400。

### `POST /api/journal/{date}/assets` 与 `GET /api/journal/assets/{date}/{filename}`

- [x] 图片只接受 PNG、JPEG、GIF 或 WebP，单张不超过 5 MB，非法内容不落盘。
- [x] 附件写入 `LIFE_OS_HOME/attachments/journal/{date}/`，返回同源受控 URL，路径不能越过运行时目录。
- [x] 已保存图片可由 Markdown 预览读取；响应不暴露运行时绝对路径。
- [x] 图片上传只允许设备本地今天，非今天返回 409；既有历史附件仍可读取和导出。

### `GET /api/journal/{date}/export`

- [x] 单日日记导出为 UTF-8 Markdown，并写入 `LIFE_OS_HOME/exports/journal/`。
- [x] 所引用的本地日记图片转换为内嵌 data URI，使导出的单个 Markdown 文件不依赖正在运行的服务。
- [x] 无日记时返回 404；图片缺失或导出写入失败时返回明确错误。

## 个人财务

### `GET|POST|PUT /api/finance/accounts`

- [x] 可创建、列出和更新资产/负债账户，支持现金、银行、信用卡、投资和其他类型。
- [x] 信用卡必须使用负债性质，`billing_day` 接受 1–28 的整数并默认使用 18；其他账户不能保存账单日。
- [x] 默认只返回启用账户，`include_inactive=true` 可返回停用账户及原 ID。
- [x] 资产期初余额不得为负，负债期初余额必须为零或负数；非法金额不写入。
- [x] v0.1 只接受 CNY，不伪造无汇率依据的多币种总额。

### `GET|POST|PUT|DELETE /api/finance/transactions`

- [x] 支持收入、支出和两个不同账户之间的转账，账户方向组合非法时返回 400。
- [x] 金额必须大于零且最多两位小数，中文分类、说明和兼容备注能无损往返；新前端省略 `note` 时不会清空旧备注。
- [x] 查询支持 `date`、`type`、`account_id`、分类名称子串和 `include_archived`，分类匹配不区分大小写，默认不返回已归档流水。
- [x] DELETE 执行幂等软归档；归档流水不再改变账户余额、当日收支或总体汇总。
- [x] `POST /api/finance/transactions/{id}/restore` 幂等恢复归档流水；前端可从分类引用提示按日期、分类和 ID 定位后执行恢复。
- [x] 停用账户不能用于新流水，但保留历史流水和汇总影响。

### `POST /api/finance/accounts/{account_id}/balance-adjustments`

- [x] 只接受 `target_balance`，金额最多两位小数；使用系统当天并由服务端计算差额，客户端不能提交差额或伪造流水方向。
- [x] 差额为正时生成指向该账户的收入方向流水，差额为负时生成来自该账户的支出方向流水；响应同时返回调整前余额、目标余额、有符号差额和生成的流水。
- [x] 自动流水固定使用“账户金额调整”说明并标记 `is_adjustment=true`，改变账户余额、资产、负债和净资产，但不进入当日或期间收支与净现金流。
- [x] 目标与当前余额相同返回 409，不生成零金额流水；不存在账户返回 404，停用账户或非法金额返回 400，失败时不产生部分写入。
- [x] 调整流水不允许通过普通 PUT 编辑；可执行软归档以撤销其余额影响，并重新发起调整。

### `GET /api/finance/summary`

- [x] 返回账户当前余额、总资产、总负债和净资产，金额统一为两位小数字符串。
- [x] `date_from`/`date_to` 限定收入、支出和净现金流统计期间，不改变当前账户余额口径。
- [x] 转账改变两个账户余额但不计入收入、支出或净现金流。
- [x] 非法日期或起始日期晚于结束日期时返回 400。
- [x] 汇总由 SQLite 条件聚合和按账户分组计算，不把全部流水实体加载到 Python 内存；结果与逐笔计算一致。

### `GET /api/finance/reports?date_from={date}&date_to={date}`

- [x] 日期范围为必填且使用 `YYYY-MM-DD`；缺失、非法或起始日期晚于结束日期时返回 400。
- [x] `by_date` 覆盖范围内每个自然日，逐日返回收入、支出、净现金流，以及当天期末总资产、总负债和净资产；无流水日期保持零收支并延续资产状态。
- [x] `by_category` 把空分类归为“未分类”，按分类返回收入、支出、净现金流和流水笔数，并按收支总额稳定排序。
- [x] `category_series` 为每个分类返回覆盖完整日期范围的收入、支出和净现金流逐日序列，缺失日填零，供可选系列的按日期分组柱状图使用。
- [x] 转账不计入收支或分类汇总；账户金额调整不计入收支，但其余额影响进入发生日及之后的资产、负债和净资产。
- [x] 报表读取 SQLite 必要列和分组基线，不通过 `list_transactions()` 装载完整流水实体；响应金额统一为两位小数字符串。
- [x] 财务报表模块位于账户、账期和流水模块之后；资产走势与流水走势各占一行，不在宽屏下并排压缩。
- [x] 两张走势图分别提供必填的横轴起点和横轴终点，范围校验独立；更新其中一张只请求并替换该图及对应精确明细，不改变另一张图的范围。
- [x] 快速连续提交横轴范围时，仅最后一次请求结果可以更新对应走势图；失败显示可见状态且不清空另一张图。

### `GET /api/finance/credit-cards/{account_id}/cycle?as_of={date}`

- [x] 仅接受信用卡账户；普通账户返回 400，不伪造账期。
- [x] 按账单日返回上期起始日、上期账单日、当前账期起止日和下一账期起始日；跨年、跨月自动滚动。
- [x] 返回上期账单、本期已还、入账抵扣、剩余待还、本账期消费、当前总欠款及 `paid|unpaid` 状态，金额统一为两位小数字符串。
- [x] 信用卡消费通过支出增加负债，资产账户转入信用卡的转账作为还款；还清上期账单不会抹去本账期新增消费。
- [x] `as_of` 只读取不晚于该日期的未归档流水，历史账期与未来已规划流水不会串入当前状态。

### 日期聚合中的财务数据

- [x] `GET /api/day/{date}` 的 `finance` 固定包含当日收入、支出、净现金流和流水列表，无数据时返回稳定零值结构。
- [x] 不同日期的流水不串数据；转账显示在当日流水中，但不改变当日收支。
