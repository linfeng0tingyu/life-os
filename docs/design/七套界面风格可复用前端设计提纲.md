# 七套界面风格可复用前端设计提纲

## 一、用途与适用边界

本文把 Life OS 已实现的默认、古风竹青、古风藏青、古风水色、新拟物派、macOS 毛玻璃和吉卜力风格，整理为可以迁移到其他桌面端或 Web 软件的前端设计基线。它描述的是表现层设计系统，而不是 Life OS 的业务结构；接入新软件时可以替换产品名称、Logo、导航、模块和技术框架，但应保留语义 Token、组件状态、响应式规则与可访问性约束。

七套主题共用同一套信息架构、DOM 或组件树、交互行为和数据接口。主题只允许改变颜色、字体、圆角、边框、阴影、背景纹理、图标描边与少量非信息性装饰，不得借切换主题增删功能、改变字段顺序、交换状态含义或触发业务写入。

“吉卜力风格”在其他公开产品中建议命名为“温暖自然动画风”。它只复用温暖天空、草木、奶油纸面和圆润手绘感，不使用具体角色、场景、截图、剪影或其他受保护素材。“macOS 毛玻璃”同样只描述通用的半透明玻璃视觉，不复制系统专有图标、窗口交通灯或操作系统界面。

## 二、设计系统总结构

可复用实现分为四层：

```text
基础语义层
├── 色彩、字体、间距、圆角、阴影、动效 Token
│
组件层
├── 导航、按钮、输入、卡片、标签、提示、指标、列表
│
主题层
├── 七套 Token 值与有限的主题装饰
│
页面层
└── 业务布局、数据状态和领域模块
```

推荐文件结构如下；它不依赖 React、Vue、Svelte 或原生 HTML，使用任何框架时都应维持相同职责边界：

```text
styles/
├── tokens.css       # 默认 Token 与尺寸刻度
├── base.css         # Reset、排版、焦点和 reduced-motion
├── layout.css       # 应用外壳与响应式布局
├── components.css   # 跨页面组件
├── themes.css       # 六套非默认主题覆盖
└── pages/           # 只含业务页面特有布局

scripts/
└── theme.js         # 主题白名单、应用、持久化与恢复
```

主题根节点统一使用 `data-theme`：

```html
<html data-theme="default">
```

允许值固定为：

| 中文名称 | 稳定标识 |
| --- | --- |
| 默认 | `default` |
| 古风竹青 | `bamboo` |
| 古风藏青 | `indigo` |
| 古风水色 | `water` |
| 新拟物派 | `neumorphism` |
| macOS 毛玻璃 | `macos-glass` |
| 吉卜力风格／温暖自然动画风 | `ghibli` |

## 三、共用视觉基线

### 3.1 页面气质

整体基线是“安静但不沉闷，现代但不冰冷，克制且有辨识度”。信息层级优先依靠留白、字号、字重、文字颜色、细分隔线和低饱和表面差异建立，避免用大面积高饱和颜色、过量悬浮卡片、复杂渐变和持续动画制造层级。

默认与三套古风主题带有现代东方气质，但不使用祥云、卷轴、印章、仿古纹样、毛笔字或红金主视觉。东方感来自暖白纸面、综合色板、字体节奏、细线边界和克制留白。

### 3.2 布局与响应式

桌面端采用固定侧栏与自适应主内容区。侧栏基准宽度为 `15rem`；主内容区使用流式宽度，不设置造成右侧空白的固定页面宽度。常用页面可采用 `minmax(0, 1fr) minmax(19rem, 25rem)` 的主次双栏，模块内部再按需要使用二至四列。

| 视口范围 | 布局行为 |
| --- | --- |
| `> 68rem` | 固定左侧栏，主内容使用全部剩余宽度。 |
| `≤ 68rem` | 侧栏转为顶部区域，导航横向滚动，主题选择器横排。 |
| `≤ 52rem` | 主次内容合并为单列，优先操作区置顶。 |
| `≤ 36rem` | 模块、指标和表单单列；标题栏纵向排列；隐藏非必要说明。 |

页面最小支持宽度为 `20rem`。所有网格子项设置 `min-width: 0`，文本、金额和表格必须有换行、截断或横向滚动策略，不能依赖固定桌面分辨率。

### 3.3 间距、尺寸与排版

通用间距刻度为 `0.25rem、0.5rem、0.75rem、1rem、1.25rem、1.5rem、2rem、2.5rem`。正文基准为 `0.9375rem`、行高 `1.6`；页面标题约 `1.75–2rem`，区块标题 `1.25rem`，辅助说明 `0.75–0.82rem`。指标数字使用等宽数字特性 `font-variant-numeric: tabular-nums`。

按钮最小高度 `2.5rem`，图标按钮约 `2.35rem × 2.35rem`。普通主题的控件圆角约 `0.5rem`、模块圆角约 `0.625rem`；需要更强风格化时由主题 Token 覆盖，组件内不得硬编码另一套圆角。

字体只使用本地系统字体回退，不依赖网络字体。正文应保持良好中文可读性；宋体、仿宋和楷体只用于指定主题与标题层级，不承担密集的小字号表单信息。

### 3.4 图标与品牌

图标统一使用同一套圆角线性 SVG，建议采用 Lucide 或同等开放图标集。基础尺寸为 `18px` 左右，使用 `currentColor`，不得混用 Emoji、填充图标、不同透视角度或来源不明的位图。每套主题可以调整描边粗细，但不能更换同一操作的图形语义。

Logo 属于产品品牌资产，不属于主题资产。移植到其他软件时应替换为目标产品 Logo；所有主题共用同一 Logo 结构，只允许调整容器背景、留白和对比度，不为每个主题制作含义不同的 Logo。

### 3.5 交互、状态与可访问性

所有主题都必须提供默认、悬停、按下、焦点、禁用、加载、成功、警告和错误状态。颜色不是唯一提示：当前导航同时使用边线、浅底和字重；财务类型同时使用文字标签与色线；错误同时使用图标、文案和边框。

普通过渡控制在 `150–250ms`，基准为 `180ms ease`。允许轻微位移、阴影变化、图标短促旋转或缩放，不允许持续漂浮、整页飞入、频繁缩放和影响阅读的循环动画。必须响应 `prefers-reduced-motion: reduce`，将动画和过渡压缩到近乎即时。

键盘焦点使用至少 `3px` 的清晰外轮廓并与组件保持偏移；文本与背景、重要控件与背景应达到 WCAG AA 的常规对比要求。透明或柔和主题不能以牺牲可读性换取视觉效果。

## 四、Token 契约

以下 Token 是七套主题的公共接口。页面和组件只能引用语义名称，不直接引用某个主题的十六进制颜色。

```css
:root {
  --background: #f5f3ed;
  --surface: #fbfaf6;
  --surface-muted: #eceae3;
  --text-primary: #242927;
  --text-secondary: #66706c;
  --text-muted: #929995;
  --border: #dcdcd4;
  --border-strong: #c6cbc5;

  --primary: #3f625f;
  --primary-hover: #345552;
  --primary-light: #dce8e4;
  --on-primary: #ffffff;
  --focus: #1f6964;
  --cyan: #729b99;
  --jade: #5e8076;
  --vermillion: #b95549;
  --gold: #a58955;
  --sidebar: #efede6;

  --module-status: #eef4f1;
  --module-focus: #fbf3e8;
  --module-rhythm: #eaf3f3;
  --module-habits: #edf4ee;
  --module-notes: #f3eff3;
  --module-finance: #f7f1e8;

  --finance-asset: #356574;
  --finance-liability: #955951;
  --finance-income: #47745d;
  --finance-expense: #b95549;
  --finance-transfer: #716482;
  --finance-neutral: #987a48;
  --finance-flow-surface: #eaf2ed;
  --finance-account-surface: #e8eff2;

  --font-ui: "Times New Roman", "PingFang SC", "Microsoft YaHei", sans-serif;
  --font-title: "Times New Roman", "Songti SC", "STSong", serif;
  --radius-control: 0.5rem;
  --radius-module: 0.625rem;

  --shadow-panel: 0 0.4rem 1.5rem rgb(36 41 39 / 4%);

```

业务项目可以重命名六个 `--module-*` Token，但应保留“不同信息域可以有低饱和背景差异”这一机制。新增语义色时必须先定义用途，再为七套主题分别校准，不能在页面 CSS 中临时增加无语义颜色。

## 五、七套风格定义

### 5.1 默认：现代东方极简

默认主题是最稳定、最中性的回退样式，适合生产力、知识管理、健康、财务和个人工具。背景使用暖白 `#F5F3ED`，纸面 `#FBFAF6`，主要文字 `#242927`，青黛主色 `#3F625F`，天青 `#729B99`，朱砂 `#B95549`，赭金 `#A58955`。侧栏为浅暖灰 `#EFEDE6`。

模块使用细边框、小圆角和几乎不可察觉的阴影；不同信息域以青、米、蓝、绿、藕紫和茶色浅底区分。图标描边约 `1.7px`，按钮只做轻微位移和短阴影。英文与数字可使用 Times New Roman，中文依次回退到苹方、微软雅黑或宋体。该主题不使用背景纹理，也不追求明显材质感。

### 5.2 古风竹青：宣纸、竹叶与温润木色

竹青主题以 `#789262` 为主色，搭配宣纸背景 `#F1F0E3`、象牙表面 `#FBF8EC`、墨绿文字 `#273426`、木赭金 `#A77D48` 和朱砂 `#A65343`。侧栏为灰竹色 `#E1E6D2`，主要按钮文字用深墨色 `#172012`。

六类模块分别使用灰竹 `#E4EAD4`、麦色 `#F3DFBD`、水青 `#D9E8E5`、嫩叶 `#DCE8C8`、浅陶 `#EEDDD5` 和茶纸 `#F1E4CC`，不可只通过同一绿色调整亮度。页面可加入极淡的竖向纸纹和暖色光斑；模块使用竹青左侧线、木色上边线和右上双短线印记。控件圆角约 `0.22rem`，模块圆角约 `0.28rem`，图标描边约 `1.45px`。标题优先仿宋，正文优先宋体，装饰必须保持抽象和轻量。

### 5.3 古风藏青：蓝布封面与秩序感

藏青主题以 `#2E4E7E` 为主色，背景 `#ECEFF3`，瓷白表面 `#F8F6F1`，深蓝墨文字 `#17263B`。固定侧栏使用深藏青 `#243E63`，配合铜金 `#A9834D`、松石绿 `#4E7167`、朱砂 `#A94F4C` 与少量藕紫。

这是七套主题中唯一使用显著深色侧栏的方案。侧栏正文使用浅蓝灰，当前导航由铜金边线、半透明亮层和白字共同表达；主内容仍保持浅色阅读面。六类模块分别使用蓝灰 `#E1E6ED`、铜纸 `#F2E6D2`、水蓝 `#DCE8EF`、松灰 `#E1E9E2`、藕灰 `#E8E2EC` 和浅藏青 `#E1E7F0`。控件和模块圆角与竹青一致，图标保持细线工笔感，金额和统计数字必须使用等宽数字。

### 5.4 古风水色：江南水面、雾气与浅玉

水色主题以 `#88ADA6` 为主色，背景 `#EDF6F4`，清白表面 `#FBFDFC`，水墨文字 `#233D39`，远山蓝 `#709BAD`，柳叶绿 `#5D8874`，沙金 `#AA8B58`，珊瑚朱 `#B45F52`。侧栏为浅水色 `#DEECE8`。

六类模块分别使用浅玉 `#D8EAE5`、莲藕粉 `#F1E1E3`、水蓝 `#D4E8EE`、浅柳 `#E0EAD4`、灰紫 `#E9E0EC` 和浅青 `#E0EEEA`。背景可使用白雾光斑、淡蓝水影和极弱斜向波纹；模块采用天青左侧线与柔和的大范围阴影。控件圆角约 `0.35rem`，模块圆角约 `0.42rem`。它必须呈现水、岸、草木和花色的综合色阶，不能退化为青绿色灰度主题。

### 5.5 新拟物派：同色基面与凹凸层级

新拟物主题使用统一冷灰蓝基面 `#E7ECF0`，表面与背景同色，主要文字 `#26333B`，主色 `#4F716F`。明暗成对阴影建立物理层级：面板使用 `10px 10px 24px #C7CDD2` 与 `-10px -10px 24px rgb(255 255 255 / 88%)`，按钮使用约 `4px` 的同类双向阴影；输入框、选中导航和部分指标使用内阴影。

卡片和侧栏不使用明显实线边框，控件圆角约 `0.95rem`，模块圆角约 `1.35rem`，图标描边约 `1.9px`。凸起代表普通可操作表面，凹陷代表输入、已选择或嵌入区域，但任何状态都必须再由文字、焦点环或色彩确认。不要把所有文本和图标做成低对比浮雕，也不要在小尺寸密集列表中叠加多层阴影。

### 5.6 macOS 毛玻璃：透明层、模糊与环境色

毛玻璃主题的底色为 `#DCE8F2`，通过青绿、天蓝与暖橙径向渐变制造环境光。主表面使用约 `52%` 白色，弱表面使用约 `62%` 的浅蓝灰，边框为约 `68%` 白色，主色 `#426F78`，正文 `#20303C`。

侧栏、顶栏和模块使用 `backdrop-filter: blur(22px) saturate(135%)`，控件圆角约 `0.8rem`，模块圆角约 `1.15rem`，图标描边约 `1.65px`。字体优先系统 UI 字体。必须为不支持背景模糊或启用高对比模式的环境提供足够不透明的回退表面；透明卡片后方不得出现高频纹理。不要模拟 macOS 窗口按钮或照搬系统专属组件。

### 5.7 吉卜力风格／温暖自然动画风：天空、草木与奶油纸面

该主题以浅天空 `#D8EDF0` 到奶油纸面 `#F5ECD7` 的背景过渡建立温暖自然氛围，主表面为 `#FFFAF0`，主要文字 `#2C3F33`，森林绿主色 `#3F6C50`，水色 `#74AEBA`，朱橙 `#C8664F`，阳光金 `#D0A044`，侧栏为 `#EFE4C9`。

卡片使用约 `2px` 米色边框、`1.15rem` 大圆角和轻微下沉阴影；标题可优先楷体，并在标题末尾使用小型金色叶点或圆点。背景允许用纯 CSS 绘制少量白色云团，图标采用约 `2px` 圆润描边，悬停只做一次短促的轻微旋转与缩放。严禁使用具体动画角色、影视画面、临摹场景、角色剪影或来源不清的手绘纹理。

## 六、语义配色与业务模块

主题色负责品牌气质，语义色负责稳定含义，两者不可混为一谈。成功、警告、危险、信息和财务类型在所有主题中都必须保持相同含义，但可以为适应背景稍微调整亮度和饱和度。

财务配色尤其不能让所有数字跟随全局主色，也不使用装饰性渐变：

| 语义 | 默认／新拟物／毛玻璃／自然动画 | 竹青 | 藏青 | 水色 |
| --- | --- | --- | --- | --- |
| 资产 | `#356574` | `#53716C` | `#2E4E7E` | `#507985` |
| 负债 | `#955951` | `#965545` | `#9E4E50` | `#9D5E60` |
| 收入 | `#47745D` | `#557447` | `#456D60` | `#527A67` |
| 支出 | `#B95549` | `#A65343` | `#A94F4C` | `#B45F52` |
| 转账 | `#716482` | `#74647A` | `#67577D` | `#766989` |
| 中性／期间 | `#987A48` | `#966D3E` | `#99723E` | `#96794B` |

金额颜色之外还应使用顶部或左侧色线、类型标签和正负号表达含义。资产总览、收支流水和账户区域使用三种协调但不同的纯色表面，避免相邻模块重复使用同一棕黄色，也避免红绿成为唯一判断依据。

非财务软件可以把这套机制映射为自己的稳定语义，例如“正常／阻塞／进行中／已完成／同步／中性”，但不能让相同颜色在不同页面表达相反含义。

## 七、组件设计提纲

### 7.1 导航与应用外壳

- 桌面侧栏同时承载品牌、主导航、主题选择和本地/隐私状态，主导航使用“线性图标 + 中文名称”。
- 当前项至少同时改变边线、背景和字重；深色侧栏主题还需提升文字和图标对比。
- 小屏转为顶部横向导航时允许滚动，不压缩文字，不把主要模块藏进仅图标菜单。

### 7.2 按钮

- 主按钮使用 `--primary` 与 `--on-primary`；次按钮使用 `--surface`、`--border-strong`。
- 危险操作使用朱砂语义并要求明确文字，不用普通主色伪装。
- Hover 只做 `1px` 左上位移或阴影变化，Active 回到右下并清除阴影；新拟物与毛玻璃主题分别改用材质反馈。
- 图标按钮必须有 `aria-label` 或可见文字，触控目标建议不小于 `40px`。

### 7.3 模块、卡片与指标

- 只有具有独立语义的内容才使用模块容器，避免“每一行都是 Card”。
- 标准模块由标题、辅助说明、右侧状态/操作和内容区组成；标题与操作在窄屏改为纵向排列。
- 指标区使用色线、数值和单位三层信息；金额、日期和统计数字使用等宽数字。
- 加载骨架、空状态、错误和重试必须占据稳定空间，防止页面跳动。

### 7.4 表单、选择与弹窗

- 标签始终可见，不以 Placeholder 代替；输入、文本域和选择器使用统一边框、圆角和内边距。
- 单选分类使用可换行的分段选择或单选列表；“新增分类”等次级操作与主提交动作分离。
- 新建复杂记录可使用模态窗口或独立桌面子窗口，但主题 Token 与主窗口一致。
- 保存状态明确显示“保存中／已保存／保存失败”，错误文案靠近字段或表单顶部。

### 7.5 列表、标签与反馈

- 列表主要依赖细分隔线而不是重复卡片；末项不显示分隔线。
- 标签用于补充状态，不代替标题；胶囊形标签只用于短文本。
- Notice 和 Inline Error 使用左侧强调线、图标与文案；成功和错误不能仅靠背景色区分。

## 八、主题切换实现

主题模块必须维护允许值白名单，非法值回退为 `default`。初始化时尽早设置根节点 `data-theme`，避免先显示默认主题再闪烁。主题选择属于界面偏好，可使用 `localStorage`；桌面应用若因随机端口导致存储域变化，可增加同一 WebView 配置内的本地 Cookie 或宿主偏好文件。存储失败时不影响当前会话使用。

```js
const themes = new Set([
  "default",
  "bamboo",
  "indigo",
  "water",
  "neumorphism",
  "macos-glass",
  "ghibli",
]);

function applyTheme(candidate, persist = true) {
  const theme = themes.has(candidate) ? candidate : "default";
  document.documentElement.dataset.theme = theme;
  if (persist) localStorage.setItem("your-app.theme", theme);
  return theme;
}
```

主题切换不得请求业务 API、修改业务数据库、清空查询缓存或重新加载页面。主题选择器应显示“只改变外观，不改变数据”的说明，并通过可见状态文本告知切换结果。若应用支持 URL 预览参数，参数值也必须经过同一白名单验证。

## 九、移植到其他软件的实施步骤

1. 盘点目标软件现有颜色、字体、圆角和阴影，找出页面中的硬编码值。
2. 建立本文第四节的语义 Token；先让默认主题完整覆盖所有页面。
3. 把按钮、导航、表单、模块、状态、图表和业务语义色改为只引用 Token。
4. 在根节点加入 `data-theme`，逐套实现主题覆盖，不复制七份组件 CSS。
5. 用目标产品 Logo、导航与模块名称替换 Life OS 专属内容，保持组件状态契约不变。
6. 建立主题白名单、默认回退、即时切换与本地持久化；切换链路与业务状态解耦。
7. 逐页检查深色侧栏、透明表面、新拟物阴影、中文字体回退、财务/状态颜色和空错误状态。
8. 在桌面、平板和手机宽度完成视觉回归、键盘操作、对比度和 reduced-motion 验收。

若目标软件已使用 Tailwind、CSS Modules、CSS-in-JS 或组件库，可以把 Token 映射到其主题系统；迁移时应保留语义名称和状态矩阵，不要求沿用 Life OS 的文件名或纯 CSS 写法。

## 十、验收清单

### 10.1 功能隔离

- [ ] 七个主题选项均能即时生效，非法值稳定回退默认主题。
- [ ] 切换主题不刷新页面、不调用业务 API、不修改业务数据。
- [ ] 刷新与应用重启后恢复偏好；清除界面缓存后回到默认主题。
- [ ] 七套主题共用同一组件结构、焦点顺序、字段和操作语义。

### 10.2 视觉一致性

- [ ] 品牌主色、语义色和模块表面职责清晰，没有页面级随意色值。
- [ ] 竹青、藏青和水色拥有不同综合色板，而不是同一界面的色相或灰度替换。
- [ ] 新拟物的凹凸关系一致；毛玻璃有不支持模糊时的回退；自然动画风不含受保护素材。
- [ ] 财务或其他专业语义不依赖全局主色，不使用难以判断含义的渐变。
- [ ] 图标来自同一线性图标体系，尺寸、描边、对齐与按钮状态一致。

### 10.3 响应式与可访问性

- [ ] 至少在 `1280px`、`768px` 和 `375px` 宽度下完成关键页面检查，无非预期横向溢出。
- [ ] 键盘可访问导航、主题选择、表单、弹窗和主要操作，焦点始终清晰可见。
- [ ] 正文、次级文字、按钮和透明表面满足实际阅读对比度。
- [ ] 状态不只靠颜色表达；缩放到 `200%` 后功能和信息仍可使用。
- [ ] `prefers-reduced-motion` 下关闭非必要动画，主题资源不依赖网络字体、远程脚本或追踪服务。

## 十一、移植时应替换与应保留的内容

| 类别 | 移植到新软件时的处理 |
| --- | --- |
| 产品名称、Logo、业务导航 | 必须替换为目标产品内容。 |
| Life OS 的六类模块名称 | 按目标领域重命名，但保留低饱和分区机制。 |
| 七套主题标识 | 建议保留稳定英文键；中文显示名可本地化。 |
| Token 契约与状态语义 | 应保留，必要时只扩展不破坏原含义。 |
| 组件结构与响应式断点 | 可按产品密度调整，但七套主题必须共享同一结构。 |
| 精确色值、圆角和阴影 | 可直接使用；若因品牌调整，应逐主题整体校准而非局部替色。 |
| 吉卜力、macOS 名称 | 内部设计沟通可保留；公开产品建议改用通用描述性名称。 |

这套设计系统的核心不是七组独立皮肤，而是一套稳定的语义组件，通过七组有完整色彩逻辑和材质规则的表现层参数，形成不同气质。只要新软件坚持这一边界，就能复用视觉风格而不复制 Life OS 的业务耦合。
