# Life OS M6 健康、日记与财务闭环建设记录

## 阶段结论

M6 已完成健康状态、日记和个人财务的主要使用闭环。该阶段复用 M2–M3 已完成的业务表、领域服务和统一 API，不新增业务表；为了让财务分类复用可创建单选组件，数据库 schema 从 v3 升到 v4，并把 `categories.scope` 扩展为 `task`、`habit` 与 `finance`。结构化数据继续写入 `LIFE_OS_HOME/database/life.db`，日记图片与导出文件分别保存在同一运行时根目录下的 `attachments/` 和 `exports/`，未增加外部服务、浏览器存储中的权威数据或不可迁移路径。

## 生活节律闭环

新增 `/health?date=YYYY-MM-DD` 页面，支持体重、前一日入睡时间、睡眠时长、睡眠质量、精力、情绪、身体状态、运动分钟和备注。普通修改在 800 毫秒防抖或失焦后保存；保存期间的新输入以修订号区分，不会被较早响应覆盖。失败时表单值保持原样并提供重试入口。

2026-09-23 的追加调整移除了醒来时间和“手动修正”模式。入睡时分固定组合为记录日前一天的带时区 ISO 时间，睡眠时长直接以小时、分钟填写并换算成不超过 1440 的整数分钟；领域服务仅为兼容旧数据库推导 `sleep_end`。Today 与 Calendar 的轻量摘要仍只显示睡眠时长、体重、运动和身体健康，详细字段仅在生活节律页展开。

## 日记闭环

新增 `/journal?date=YYYY-MM-DD` 页面，以 Markdown 原文编辑并提供安全实时预览。工具栏可插入设备当前的 24 小时制 `HH:mm`、一级至三级标题和本地图片；图片经过 PNG、JPEG、GIF 或 WebP 文件签名及 5 MiB 大小校验后，原子写入 `LIFE_OS_HOME/attachments/journal/{date}/`，正文只保存同源受控 URL。预览器使用 DOM 节点构造标题、列表、引用、分隔线、粗体、行内代码和受控图片，不执行正文 HTML 或外部图片地址。

停止输入 1.2 秒后自动保存，同时显示“等待保存、保存中、已保存、保存失败”和最后成功保存时间。保存请求发出后若继续输入，新内容保持在编辑器中并在前一次成功后再次保存；保存失败不会清空输入。存在未完成保存时，页面关闭或刷新会触发浏览器离开保护。单日“导出 Markdown”会先等待当前内容保存，再把正文中的本地图片转成 Base64 数据 URI，生成可脱离附件目录阅读的 `LIFE_OS_HOME/exports/journal/{date}.md` 并触发下载。

## 财务闭环

新增 `/finance?date=YYYY-MM-DD` 页面。账户模块支持资产/负债账户创建、编辑、启用和停用，覆盖现金、银行卡、信用、投资与其他类型；页面不再提供“显示停用账户”筛选，账户列表直接保留停用项，确保用户仍可重新启用。流水模块支持当天收入、支出和两个不同账户之间的转账，包含日期、金额、账户方向、分类和说明，可编辑或软归档；旧备注字段仅为数据兼容与导出保留。分类采用 `finance` 作用域的单选组件，并可在记账窗口中现场创建；schema v3 升级时会把已有流水的非空分类回填为选项。所有财务写入均由用户显式提交，提交期间禁用表单；失败时窗口保持打开且输入不被重置。

2026-09-24 增加“再记一笔”。该动作先通过原流水接口保存当前记录，成功后保留日期、类型、适用账户与分类，清空金额和说明并把焦点交给下一笔金额；编辑已有流水时隐藏此按钮。连续录入不改变数据库结构、金额精度、账户方向校验或归档规则，每次操作仍对应一条独立事务。

财务分类同日接入共享分类管理控件，支持搜索、新增、排序和删除未使用项。旧自由文本分类继续通过隐藏原生选择值兼容显示；任何当前或已归档财务流水仍引用分类时，服务端拒绝删除，避免总体汇总、导出或历史回看失去原始分类语义。

总体摘要显示总资产、总负债、净资产、期间收入、期间支出和期间净现金流，并列出账户当前余额。日期区间只影响期间收支，不改变当前余额；转账只改变两个账户余额，不计入收入、支出或净现金流。账户、流水和摘要在成功写入后共同刷新，避免局部界面显示旧值。

2026-09-28 增加账户余额调整。资产概览中的每个启用账户提供“调整余额”，窗口展示账户、当前余额和系统当天，只要求填写调整后的实际余额。服务端在单一事务中重新计算当前余额与差额，按差额方向自动生成说明为“账户金额调整”的流水；正差额进入账户，负差额离开账户。schema 从 v5 升到 v6，并为流水增加 `is_adjustment`：调整流水参与余额、总资产、总负债和净资产计算，但从收入、支出、净现金流、信用卡消费与入账抵扣统计中排除。

调整流水由系统生成，普通流水窗口不可编辑；用户可归档该流水撤销其余额影响，再按实际金额重新调整。目标余额与当前余额相同返回 409，不制造零金额记录；停用账户必须先重新启用。schema v5→v6 迁移只新增带默认值的布尔标记，既有流水全部保持普通流水语义，金额、账户方向、说明和归档状态均不改写。全量 CSV 导出同步增加 `is_adjustment`，确保迁移与外部核对时可以识别调整来源。

### 信用卡账期增量

财务闭环后续增加信用卡账户语义，并把 schema 从 v4 升到 v5。信用卡固定使用负债性质，可设置 1–28 日的每月账单日，默认值为 18；原有 `credit` 账户迁移时自动补入 18，不修改余额或历史流水。消费继续使用信用卡账户的支出流水，还款继续使用资产账户转入信用卡的转账，因此总体负债、净资产、当日流水、备份和导出仍以同一份权威数据计算。

财务页新增“账期与还款”区域，按选定日期显示上期账单、本期已还、剩余待还、本账期消费、当前总欠款和当前账期范围，并提供“记录消费”和“信用卡还款”快捷入口。账期从上一个账单日次日开始，到账单日结束，次日自动滚动；还清上期账单后，本账期新增消费仍作为当前总欠款保留。该增量不推断银行还款截止日、最低还款、利息、分期或逾期费用。

## 日期与导航联动

侧边导航增加“节律”“记录”“财务”入口。Today 与 Calendar 共用日期详情中的三个模块分别增加管理链接，并在数据载入后携带当前日期参数。历史日期可以直接进入对应记录；未来日期在独立健康、日记和财务页归一到系统今天，避免提前生成事实记录。日历中的未来规划仍由任务系统负责。

- `python -m pytest`：121 项全部通过，新增覆盖 schema v3→v4、财务分类作用域、图片格式与大小边界、受控附件读取和自包含导出。
- Node.js 语法检查：`health.js`、`journal.js`、`markdown-preview.js`、`finance.js` 与 `app.js` 均通过。
- 独立临时运行时验证：记录日 9 月 18 日的 23:30 入睡被保存为 9 月 17 日，7 小时 30 分钟保存为 450 分钟并正确推导兼容结束时间。
- 日记验证：标题按钮正确写入并预览一级标题，当前时间按钮插入 `HH:mm`，本地图片上传后可预览和自动保存；导出生成运行时目录内的自包含 Markdown 并触发下载。
- 财务验证：页面不存在“显示停用账户”筛选；现场创建“餐饮”分类后自动选中，使用该单选项保存流水成功。
- 2026-09-24 连续记账实机验收确认：12.34 元支出只生成一条流水；下一笔保留日期、支出类型、转出账户与分类，金额和说明为空，编辑模式入口隐藏。
- 响应式验证：390×844 视口下财务主栏转为单列，侧栏回到文档流，导航可横向滚动，页面无横向溢出。
- 桌面发行验证：PyInstaller `onedir` 重新构建成功，`LifeOS.exe --check` 返回 0；新增模板、脚本和样式与发行目录内副本的 SHA-256 一致。
- 信用卡增量验证：完整测试套件扩展为 151 项，覆盖 schema v4→v5、18 日账单边界、跨年滚动、信用卡消费、资产账户转账还款、还清后保留本账期消费及下一账期自动滚动；18 个 JavaScript 文件通过 Node.js 语法检查。PyInstaller 桌面包重建成功，冻结程序 `--check` 返回 0，并确认其初始化的数据库为 schema v5 且含 `billing_day`。
- 余额调整增量验证：完整测试套件扩展为 170 项并全部通过，覆盖余额上调、下调、负债负数余额、停用账户、相同余额冲突、调整流水归档撤销、收支统计隔离、类型筛选和 schema v5→v6 无损迁移；19 个 JavaScript 文件通过 Node.js 语法检查。根目录单文件版与便携目录版均已重建并使用独立临时运行时通过 `--check`，相关模板、脚本和样式与便携发行目录副本的 SHA-256 一致。

## 后续边界

M6 不包含预算、账单导入、多币种、投资收益分析、可执行 HTML 型富文本编辑、日记标签或健康趋势图。M6 已提供单篇日记的自包含 Markdown 导出；备份、结构化数据 CSV、全部日记批量 Markdown 导出、恢复说明和跨目录迁移演练继续由 M7 完成。全新 Windows 设备上的桌面发行验收属于 M8。
