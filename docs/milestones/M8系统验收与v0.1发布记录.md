# Life OS M8 系统验收与 v0.1 发布记录

## 阶段结论

M8 完成 Life OS `0.1.0` 的初步发布验收。应用代码版本、Python 项目版本和 Windows 文件版本已经统一；M0–M7 建立的日期聚合、业务闭环、桌面封装与数据保护能力进入首个可用版本。本阶段没有修改数据库 schema，现有 schema v1–v3 仍可迁移到 schema v4。

## 自动化验收

完整测试套件扩展到 148 项，覆盖既有 API、领域服务、数据库迁移、七套主题、桌面宿主和 M7 数据保护，同时新增以下 M8 发布验收：

- `0.1.0` 版本在应用、`pyproject.toml` 和发行元数据中保持一致，不包含开发版后缀。
- Waitress 在随机 `127.0.0.1` 端口并发处理 24 个健康检查请求，响应全部成功，停止后端口释放。
- 从分类、任务、习惯、健康、日记和财务一路完成日期聚合，再生成一致性备份与开放格式 ZIP 导出。
- 模拟导出写入失败时清理所有不完整文件，原 SQLite 数据仍可读取。
- 发行打包脚本生成以 `LifeOS/` 为根的 ZIP，并生成与文件内容匹配的 SHA-256 校验文件。
- GitHub README 引用的指定 Logo 与七套真实主题截图全部存在。

GitHub Actions 首轮 Windows 测试发现：当运行机处于 UTC 时区时，显式传入 `+08:00` 的备份时间会被转换为本机时区，导致备份文件日期变化。数据保护服务现仅为无时区时间补充本机时区，并完整保留调用方传入的带时区时间；修复后本地 148 项测试与云端 Windows 流水线均已通过。流水线使用官方当前稳定主版本 `actions/checkout@v7` 与 `actions/setup-python@v7`，不再触发 Node.js 20 弃用告警。

依赖检查 `pip check` 通过；核心 JavaScript 文件通过 Node.js 语法检查；`git diff --check` 无内容错误。API 继续只绑定回环地址，Waitress 不暴露 traceback，日志回归测试确认日记正文和健康详情不会写入诊断日志。

## 界面与主题验收

在独立演示运行时写入任务、习惯、睡眠、体重、运动、身体状态、Markdown 日记和收入/支出示例，Today Dashboard 能同时呈现日期标记、三个事项、两项习惯、生活节律和当日现金流。浏览器控制台无 error 或 warning。

默认、古风竹青、古风藏青、古风水色、新拟物派、macOS 毛玻璃和吉卜力七套主题均由实际页面以 1440×1000 视口渲染，展示图保存于 `docs/images/themes/` 并进入 GitHub README。新增的 `?theme=<id>` 仅用于当前页面预览，主题值仍受七个白名单限制，不写入业务数据；常规下拉选择与 WebView 偏好恢复逻辑不变。

## 桌面发行物

使用 Python 3.14.6、PyInstaller 6.22.3、pywebview 6.2.1 和 Waitress 3.0.2 重建 `onedir` 发行目录。冻结程序在清除 Python 路径后的进程环境中使用全新绝对 `LIFE_OS_HOME` 执行 `--check` 成功，生成 schema v4 数据库和每日备份；运行时元数据记录版本 `0.1.0`，`LifeOS.exe` 的文件版本与产品版本均为 `0.1.0.0`。

发布脚本生成：

- `release/LifeOS-v0.1.0-windows-x64.zip`
- `release/LifeOS-v0.1.0-windows-x64.zip.sha256`
- 最终构建大小：`21,557,515` 字节
- 最终构建 SHA-256：`6b28a2b30930f0664bcd0cc05b7ae3be6303d7f7a316dc7a70c98a1e44f1a9c0`

ZIP、哈希和 `dist/` 属于可重建发行产物，受 Git 忽略，不写入源码提交；GitHub Release 单独上传 ZIP 与校验文件。

## GitHub 发布边界

GitHub 源码仓库为 <https://github.com/linfeng0tingyu/life-os>，只发布 Life OS 项目子目录，不发布上级 `AI-Documents` 仓库、个人运行时数据、`.venv`、构建缓存或演示数据库。仓库包含 GitHub Actions Windows 测试工作流、Logo、七套主题截图、使用说明、迁移指南、变更记录和完整源码。

仓库首次发布时采用 private，以避免在许可证和公开范围尚未确认时意外公开内容。用户随后确认当前版本允许开源并选择 MIT License；源码根目录现包含标准 `LICENSE`，Python 项目元数据、README、Changelog 与 Windows 发行包均同步声明或携带许可证，GitHub 仓库切换为 public。

## 初步验收的边界

本次完成的是同一台 Windows 11 设备上的独立运行时、无 Python PATH 冻结启动、不同绝对路径迁移、备份恢复、并发和错误注入验收。尚未取得另一台物理 Windows 10/11 设备的硬件独立验收记录，也未进行代码签名，因此首次下载时 Windows 可能显示未知发布者提示。这两项不阻断 v0.1.0 初始发布，但应在后续维护版或正式公开推广前补充。
