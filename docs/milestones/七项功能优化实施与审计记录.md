# Life OS 七项功能优化实施与审计记录

## 实施范围

本次增量在 schema v5 与统一 `LIFE_OS_HOME` 数据边界内完成，没有新增、删除或重命名数据库列，也没有触发真实运行时迁移。习惯与生活节律新增自然周、自然月和自然年报表；习惯分类组件修复异步读取覆盖刚创建分类的竞态，并在每次打开习惯编辑窗口时重新同步；习惯图标入口从当前界面与新请求移除，但旧字段保留。

原阶段曾把睡眠界面收敛为入睡时分与小时、分钟时长；2026-09-28 后续需求又取消独立睡眠模块和精确睡眠录入，当前只使用五档睡眠情况区间，旧数据库列仅作兼容保留且不进入当前统计。日记页新增月历索引，今天保持完整编辑能力，其他日期只显示安全 Markdown 预览；月历位于文本编辑与预览模块下方，非今天写正文和上传图片同时受到 API 409 保护。任务快捷操作固定为两行三列，财务“记一笔”只保留说明字段，编辑旧流水时不会清空兼容备注。

## 数据与计算审计

统计报表不建立缓存或快照表，直接批量读取现有明细。习惯报表固定读取一次习惯清单和一次区间日志，不按日期或习惯重复查询；健康报表批量读取区间记录及其运动种类关联，按当前睡眠情况、体重、运动分钟、运动种类、精力、情绪和身体状态汇总，不再计算旧精确睡眠时长。未来日期使用 `null`，缺失记录不插值。日记月度索引依赖 `journals.date` 唯一索引，仅返回日期与更新时间，不读取整月正文。

财务总览原先把全部未归档流水实体载入 Python 后再计算余额和期间收支。此次改为 SQLite 条件聚合与转入/转出账户分组查询，结果合同、整数分精度、停用账户和归档排除规则保持不变。该修改以现有财务服务/API 回归测试验证等价性，避免随历史流水增长线性占用 Python 对象内存。

本轮未调整任务与习惯 `sort_order` 的数据模型。相邻移动仍可能在长期使用后出现重复值，但查询始终以 `sort_order, id` 提供确定顺序；事务内重排属于独立的数据行为变更，建议在出现真实排序异常后单独设计和迁移，不在本轮验收尾声扩大范围。

## 使用体验审计

统计图表使用本地 CSS 和原生 DOM，不增加 CDN 或构建依赖，并同时提供数值表。周/月/年切换、上一周期、下一周期与回到本期保持一致；日记月历位于文本编辑与预览模块下方，并用独立的“有记录”“所选日期”和“今天”状态，历史无记录时不会误导为可编辑。任务按钮在状态变化和排序边界下保持位置稳定，主要操作使用主题 Token，不为七套主题复制业务样式。

代表性窄屏下，统计控制组、报表表格、日记双栏和日记月历均有单列或横向滚动降级。生活节律的睡眠与健康状态模块在双栏时等高，并按容器宽度自动换列；记录、财务与设置页移除固定页面最大宽度，全局模块内边距使用 `clamp()` 平滑缩放。使用隔离运行时逐页检查今日、日历、任务、习惯、节律、记录、财务和设置：1280px、768px、375px 均无页面级横向溢出，1920px 与 2560px 能完整利用侧栏外空间，浏览器控制台无错误。

## 验证记录

最终验证结果如下：

- Python 全量测试为 163 项，全部通过；新增测试覆盖自然周期、未来空值、连续完成、节律汇总、日记月度索引与非今日写保护、旧财务备注保留、财务数据库聚合和查询计划。
- 19 个 JavaScript 文件全部通过 `node --check`，全部 Python 源文件通过 UTF-8 AST 解析，`git diff --check` 无空白错误。
- 隔离 SQLite 通过 `PRAGMA integrity_check` 与 `PRAGMA foreign_key_check`，schema 保持 v5；日记月份、习惯区间和健康区间查询计划均使用日期索引。
- `build_desktop.bat` 成功重建项目根目录单文件 `LifeOS.exe` 与 `dist/LifeOS/LifeOS.exe`，两者分别使用独立的系统临时 `--home` 完成无界面自检。
- 正式 `life-os-data/backups/` 开始和结束时均为同一 4 个文件，逐文件 SHA-256 完全一致，变化数为 0。测试、构建与自检没有读取或写入正式运行时数据库。

## 延后项

压力数据下的交互式图表虚拟化、跨字段行为相关性、任务/习惯排序归一化、日记全文搜索和新的主题截图属于后续增强。它们不影响本次七项需求的读写闭环与数据兼容，不应在未明确立项时修改 schema 或真实用户数据。

## 2026-09-24 分类管理与精简复核

本次复核把任务、习惯、日历未来规划和财务中四份结构相同的分类表单合并为一个 Jinja 宏，并把分类选择、新增、搜索、排序、删除和长列表滚动统一放入 `CategorySelect`。后端仅增加原子排序与受引用保护的删除端点，没有增加表或缓存副本；新增分类默认追加到当前作用域末尾，完整重排后使用稳定间隔，避免前端为相邻移动连续制造小数或重复顺序。

接口逐项反查确认，日期聚合、系统信息、备份恢复、分类、各领域 CRUD 和统计端点均被当前前端、自动化验收或兼容合同使用，没有可直接删除的孤立接口。数据库中的 `habits.icon`、`finance_transactions.note` 及旧睡眠兼容列已经退出当前新建界面，但仍可能保存用户历史值，并参与序列化、导出或旧版本升级；在没有迁移确认和用户授权前删除会造成数据损失，因此本轮明确保留。分类删除同样不采用级联清空，而是在任何当前、停用或归档记录仍引用时返回冲突。该结论将“简洁”限定为减少重复实现和无效查询，不以破坏历史兼容换取表面上的字段减少。

本次增量完成后，全量 166 项 pytest 测试通过；分类测试覆盖任务、习惯与财务历史引用保护、完整作用域排序及非法重排回滚。19 个 JavaScript 文件通过语法检查，根目录单文件版与便携目录版均重新构建并在独立临时运行时通过 `--check`。正式备份目录中的既有数据库文件没有被测试或构建改写，六个既有主备份的 SHA-256 与任务前基线一致，较早存在的附加手动备份和恢复安全副本的最后写入时间也早于本次实施。
